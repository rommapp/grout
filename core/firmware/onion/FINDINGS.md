# Onion findings

Pinned upstream: github.com/OnionUI/Onion v4.3.1-1 (annotated tag e351d0ee, commit 7dfc008b851398dcfe57819519efe5f958c77f65). It is releases/latest. The default branch is main. A newer prerelease tagged "latest" (2026-01-21, a rolling nightly) exists and was not used. Paths below are relative to the pinned ref.

- Layout: Onion ships no emulators preinstalled. Systems come from Package Manager packages: static/packages/Emu (the "verified" defaults) and static/packages/RApp (the "expert" alternatives). Each package's config.json rompath gives the ROM folder, and its launch.sh gives the core. Rows list the Emu package's core first, then RApp cores that share the same ROM folder. RApp packages are optional installs, so their save folders exist only once the user installs them.
- Save folder names: each one is a core's library_name. Each name was taken from a folder in static/configs/Saves/CurrentProfile/config (override or remaps, for example remaps/cap32 and remaps/FB Alpha 2012 CPS-2). Where no folder exists, the name comes from the corename in static/build/RetroArch/.retroarch/cores/<core>_libretro.info, which does not prove library_name. Those info-only names are "PUAE 2021" (amiga), "FB Alpha 2012 CPS-1", "FB Alpha 2012 CPS-3", "GW", "NeoCD", "FB Alpha 2012 Neo Geo", "TIC-80", "VICE xvic", "Virtual Jaguar", "Arduous", "QUASI88", "Neko Project II Kai", "Neko Project II", "Beetle PC-FX" and "PX68k". The last seven belong to systems that only have an RApp package, so that core is the only one there. Non-default RApp cores with no override folder were left out: Beetle Lynx, Frodo, fMSX, Gearboy, Meteor, VBA Next, Snes9x 2002, DOSBox Pure 0.9.7, DuckSwanStation Xtreme Amped, UAE4ARM, FB Alpha 2012, MAME 2000, M.B.A-mini.
- amiga saves: Onion ships an override folder "PUAE" (PUAE.opt) and none named "PUAE 2021". puae2021 is the default Amiga core, and puae_libretro.so ships with no package using it. puae2021's real library_name may therefore be "PUAE". Both are listed, in Allium's order. uae4arm's only folder is "uae4arm_chips-rtype_version", which looks like a per-game or per-version name, so it was left out.
- gba saves: v2 had ["gpSP", "mGBA"]. Upstream has ["mGBA", "gpSP", "Beetle GBA", "VBA-M"]. The Emu GBA package runs mgba_libretro, and its launch.sh imports old saves from gpSP. gpSP.opt sets gpsp_save_method = "gpSP", and the mGBA import renames gpSP files from .sav to .srm, so gpSP saves are <rom>.sav, not .srm. Beetle GBA.opt sets gba_use_mednafen_save_method = "mednafen". Grout's retroarch naming will not match gpSP saves, and possibly not Beetle GBA saves either.
- nds saves: v2 had ["DraStic"]. NDS runs standalone DraStic with HOME=Emu/NDS ("Emu/Nintendo - DS (Drastic)/Emu/NDS/launch.sh"). Its resources/settings.json sets states to /mnt/SDCARD/Saves/CurrentProfile/states/Drastic. Migration static/build/.tmp_update/script/migration/00017_drastic_migration.sh copies the old Emu/NDS/backup saves into that same folder, which suggests saves now live in ../states/Drastic. That behaviour belongs to the DraStic binary and is not proven in the repo. DraStic names saves <rom>.dsv, which retroarch naming does not match. Written as []. BIOS for DraStic is in Emu/NDS/system, outside BIOS.
- arcade: v2 had roms ["ARCADE"] plus separate cps1, cps2 and cps3 rows, and saves ["MAME 2003-Plus", CPS-1/2/3, "FB Alpha 2012 Neo Geo", "FinalBurn Neo"]. Following Allium, CPS1, CPS2 and CPS3 (separate Emu packages) moved into arcade roms, and the cps rows are gone. FBNEO (RApp fbneo) was added to roms. Saves are now ["MAME 2003-Plus", "MAME 2003-Xtreme", "FB Alpha 2012 CPS-1", "FB Alpha 2012 CPS-2", "FB Alpha 2012 CPS-3", "FinalBurn Neo"], with Neo Geo left to the neogeoaes and neogeomvs rows. MAME 2003-Plus.opt enables mame2003-plus_core_save_subfolder, so its files go under saves/MAME 2003-Plus/mame2003-plus/. Arcade folders not added: FBA2012, MAME2000, MBA, ADVMAME (advmame standalone), DAPHNE.
- odyssey and videopac: v2 used slugs odyssey and videopac. They are written as odyssey-2 and videopac-g7400 (same fix as Allium, Spruce, Knulli). Save folder "Odyssey2" became "O2EM".
- RApp ROM folders differ from v2 (v2's data matched Koriki): pc-8000 v2 [] is now ["PCEIGHTYEIGHT"] (quasi88). pc-9800-series v2 [] is now ["PCNINETYEIGHT"]. x1 v2 [] is now ["XONE"]. zx81 v2 [] is now ["ZXEIGHTYONE"] with save folder "EightyOne" (81_libretro.so ships). The RApp package names "NEC - PC-8000 (Quasi88)", but quasi88 emulates the PC-8801, so RomM's pc-8800-series may be the better slug.
- Rows v2 left empty that upstream maps: 3do ["PANASONIC"] (Opera), atari800 and atari8bit ["EIGHTHUNDRED"] (Atari800), jaguar ["JAGUAR"], pc-fx ["PCFX"], plus the RApp folders above.
- v2 folders with no upstream package: n64 ["N64"], dc ["DC"], psp ["PSP"], ps2 ["PS2"]. No Emu or RApp package uses these folders at v4.3.1-1, so all four are written as []. v2 saves "Mupen64Plus-Next", "Flycast" and "Beetle Saturn" were dropped. cave-story: nxengine_libretro.so ships, but no package uses it, so it is [].
- Other save folder changes against v2: acpc "CPC (CrocoDS)" became "crocods", with "cap32" added. amiga added "PUAE" and "P-UAE Xtreme Amped". arduboy "Ardens" became "Arduous". atari5200 added "Atari800". c64 "VICE x64, fast" became "VICE x64". dos "DOSBox-Pure" became "DOSBox-pure". g-and-w "Handheld Electronic" became "GW". gb and gbc added "TGB Dual". nes and famicom added "Nestopia". gamegear and sms added "Gearsystem" and "Genesis Plus GX". genesis and segacd added "Genesis Plus GX". snes and sfam became ["Supafaust", "Snes9x", "Snes9x 2010", "Snes9x 2005", "Snes9x 2005 Plus", "ChimeraSNES"]. tg16 added "Beetle PCE". vectrex "vecx" became "VecX" and zxs "Fuse" became "fuse" (case only). wonderswan and wonderswan-color "Beetle Cygne" became "Beetle WonderSwan". pico-8 "FAKE-08" became "fake-08", and pico gained it too. pc-9800-series added "Neko Project II".
- sgb saves: ["mGBA"] only. The Super Game Boy package runs mgba_libretro, and no RApp targets Roms/SGB.
- wonderswan-color: Onion's only WS package ("Bandai - WonderSwanColor (B. Cygne)") has extlist "ws|pc2|zip|7z" with no wsc. Unzipped .wsc files from RomM will not appear in MainUI.
- pico / pico-8: Roms/PICO is shared by the Emu fake08 core and by two RApps. "PICO-8 (Fake8 standalone)" runs FAKE08 with its own HOME. "PICO-8 (PICO-8 standalone)" runs with HOME=/mnt/SDCARD/Saves/CurrentProfile/saves/PICO-8, which puts cart data in saves/PICO-8/.lexaloffle/pico-8/cdata, named by cart id. Neither is expressible. The retro8 override folder "retro-8 (alpha)" exists, but no package uses retro8, so it is not listed (Allium lists it).
- psx: v2 "PCSX-ReARMed" is confirmed. The "Sony - PlayStation (PCSX standalone)" RApp runs pcsx with HOME set to the ROM's folder. Its saves are outside the save tree and not expressible.
- Other standalone layouts not in rows: OpenBOR (RApp, own folder), GnGeo (HOME=Saves/CurrentProfile/states, ROMs from BIOS; Roms/GNGEO not added to neogeo rows), ScummVM standalone (Roms/SCUMMVM/Shortcuts_Standalone, config Saves/CurrentProfile/config/scummvm_standalone/.scummvmrc), AdvanceMAME (Roms/ADVMAME). scummvm and openbor saves are left []. ScummVM (Emu, libretro) launches .target shortcuts from Roms/SCUMMVM/Shortcuts, which import_scummvm.sh generates from game folders in Roms/SCUMMVM.
- ports: v2 had ["PORTS"], which is kept. Upstream's Ports Collection lists .port shortcuts from Roms/PORTS/Shortcuts, with game data in Roms/PORTS/Games/<port>. A file downloaded into Roms/PORTS will not appear or launch as-is. The owner should decide whether to keep the row or empty it.
- Unmapped upstream ROM folders (RApp, no v2 row): AMIGACD (amiga-cd32), DAPHNE, EBK (bk), CHAI (chailove), EASYRPG (rpg-maker), LUTRO, LOWRESNX (lowres), MICROW8, GME, PALM (palm-os), TI83 (ti-83), THOMSON (thomson-mo5 or thomson-to), UZEBOX (uzebox), VMU (vmu), MDHACKS, PUZZLE, FBA2012, MAME2000, MBA, ADVMAME, GNGEO. Only the first folder per system is listed. Several RApps share the Emu folder.
- version.file: the Makefile writes "v$(VERSION)" (VERSION=4.3.1-1) to .tmp_update/onionVersion/version.txt, and bootScreen.c and easter.c read it. Release notes from v4.3.0 to v4.3.1-1 show no change to Roms, BIOS, Saves/CurrentProfile/saves or Imgs. v4.3.0 made the theme, favourites and recent list per profile, and added DraStic. None of these touch a field in the file, so nothing is ranged. static/configs/Saves/CurrentProfile/saves/README.txt has a stale console-to-save-folder table (e.g. ARCADE "FB Alpha", GBA "gpSP", PICO "Retro8") that contradicts the packages and was ignored.
- devices and packaging: Onion runs on the Miyoo Mini, Mini Plus (static/dist/miyoo354) and, via the 560p handling, MMv4 screens. Grout has the one miyoo mapping and no rules. The v2 miyoo.json was copied unchanged; it is byte-identical to Allium's. It has not been checked on hardware. launch.sh now sets LD_LIBRARY_PATH="$(pwd)/lib" after cd-ing into Grout/grout. config.json's icon "/mnt/SDCARD/App/Grout/grout.png" was kept. Onion apps live under /mnt/SDCARD/App (src/common/utils/apply_icons.h CONFIG_APP_PATH), and upstream app configs use both relative ("../../Icons/...", resolved from the app folder) and absolute icons (Battery Monitor, OTA update). The absolute path is correct for the App/Grout install. A relative "grout.png" would also work and would survive a renamed folder.
- Slug fix: row `pc-8000` renamed to `pc-8800-series` (package "NEC - PC-8000 (Quasi88)" runs quasi88 with rompath ../../Roms/PCEIGHTYEIGHT; RomM aliases pc88 to pc-8800-series).
