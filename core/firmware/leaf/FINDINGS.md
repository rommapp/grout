# Leaf findings

Pinned upstream: github.com/Utility-Muffin-Research-Kitchen/Leaf v0.14.0 (897cd1a603f73d82f02787dd8e4961cfa40cd136). It is releases/latest. Paths below are relative to that ref unless they name another repo.

- upstream (second repo): Leaf is the workspace orchestrator. The launcher is Utility-Muffin-Research-Kitchen/Jawaka, which has no tags. The facts below that cite Jawaka use 1a572852717babfde74038a6986c2fe6e4875590, the last main commit before v0.14.0 was published (2026-11-06T20:57Z vs 21:56Z). Those facts are proven only there.
- retroarch: left out of the file because no Leaf-repo src exists. Jawaka sets the shared config to {card}/.umrk/mlp1/retroarch/retroarch.cfg (internal/platform/paths.c jw__retroarch_shared_config_path, jw_retroarch_state_dir; UMRK_INTERNAL_DATA_PATH overrides the .umrk/mlp1 part). It sets rgui_config_directory, which would be `overrides`, to {card}/.umrk/mlp1/retroarch/.config/retroarch/config (jw__default_retroarch_config_dir). Leaf README.md proves only the sibling .umrk/mlp1/retroarch/.config/retroarch/shaders/. The hardcore setting's location was not traced.
- saves.layout: the in-repo src is the comment in scripts/retroarch_generate_metadata.py (library_name "byte-for-byte as the per-core Saves/ and States/ directory name"). The setting itself is in Jawaka paths.c: sort_savefiles_enable is forced "true" on every launch and is a protected key. savefile_directory and system_directory are also written per launch from SAVES_PATH and BIOS_PATH, else <content root>/Saves and /BIOS (jw__retroarch_storage_dirs).
- saves.naming: retroarch (.srm) is RetroArch's default. The src config/retroarch/mlp1/cores.json shows only that these cores are type "retroarch". No Leaf file names the extension.
- paths.card / second SD card: Jawaka writes saves, states and BIOS to the card the ROM came from (paths.c comment above jw__retroarch_cfg write: "sdroot_abs is the CONTENT root"). It also notes that /mnt/sdcard and /media/sdcard1 swap across reboots. v0.14.0 scans both cards. leaf_card_root returns one card (SDCARD_PATH, else the executable's card, else /mnt/sdcard), so games and saves on the second card are not modelled.
- version: Leaf has no plain version file. The version exists only in release JSON (scripts/make-sd-release-zip.sh writes .system/leaf/releases/<id>/ and leaf-update.json). [version] was left out, and nothing is ranged.
- platforms.pokemon-mini: v2 had roms [] and saves []. Upstream v0.14.0 has roms ["POKEMINI"] (config/retroarch/mlp1/systems.json, core pokemini) and saves ["PokeMini"] (cores.json config_folder; also listed in MLP1_PACKAGED_CORE_LIBRARY_NAMES). The system was added in v0.14.0: it is absent from v0.13.0 systems.json, and the release notes say so. It cannot be ranged without [version].
- platforms, standalone defaults not expressible:
  - dc defaults to flycast_standalone, n64 to mupen64plus_standalone, nds to drastic, psp to ppsspp and ports to ports, all type "path" in cores.json.
  - Their save layouts live in sibling repos (Flycast-standalone, N64-standalone, steward-fu-nds/Fun-Drastic, PPSSPP-spruce).
  - The v0.12.0 release notes put DraStic data under Saves/NDS/.
  - v2's RetroArch folders were kept for dc (Flycast, FlyCast Fast UMRK) and n64 (Mupen64Plus-Next). v2's empty saves were kept for nds and psp.
  - scripts/adb-dsperate-lifecycle.sh shows the optional DSperate core uses Saves/DSperate.
- platforms.nds bios: v2 had the default {bios}/{rel}. Upstream systems.json bios_notes says to put nds_bios_arm7.bin, nds_bios_arm9.bin and nds_firmware.bin in BIOS/NDS, so the row is written as ["{bios}/NDS/{name}"]. Unchecked: whether RomM reports these DraStic file names or the melonDS ones (bios7.bin and so on).
- platforms bios, fbneo rule: ["{bios}/{name}", "{bios}/{rel}"] is on arcade, neogeoaes, neogeomvs, cps1, cps2 and cps3. These are the rows whose folders (ARCADE, NEOGEO) default to fbneo.
  - Upstream proof: NEOGEO bios_notes "neogeo.zip (required, place in BIOS folder)", and ARCADE ignore_file_names lists neogeo.zip.
  - Unlike v2, the rule applies to every BIOS file on those rows, not only rel paths starting with fbneo/. Every file gets a root copy plus its rel copy.
- platforms bios, confirmed: amiga {bios}/puae/{name} (systems.json AMIGA bios_notes "puae/..."). saturn {bios}/SATURN/{name} then {bios}/{rel} (README.md "BIOS/SATURN/ # Saturn firmware for RetroArch and standalone selection").
- art.cover: the src is systems.json image_root (Images/<rom folder> for each system). v2's fallback for alias folders (Images/FC) is proven only in Jawaka internal/discovery/art_path.c jw_art_find_for_rom. The lookup order there is the canonical image_root, then Images/<physical folder>, then Roms/<folder>/Imgs. stage/mlp1.mk also creates a public Videos/ folder. No art.video key was added: v2 had none, and its use was not traced.
- platforms, candidates not added: naomi (Roms/NAOMI), atomiswave (Roms/ATOMISWAVE) and rpg-maker (Roms/EASYRPG, added in v0.14.0) are upstream systems with RomM slugs, but v2 had no rows for them. MAME, MAME2003, MAME2010 stay grouped under arcade, and MD32X under sega32, as in v2. The GB system also accepts an SGB folder (patterns), but sgb stays ["GB"].
- platforms colecovision, vectrex, virtualboy: the folders exist upstream, but their only cores (bluemsx, vecx, mednafen_vb) have status "missing" in cores.json. saves stays [].
- launch script: launch.sh falls back to $PAK_DIR/../../.. without checking for Roms, and does not export SDCARD_PATH when it falls back. Grout then uses the hook's walk from the executable, which does check for Roms. The two agree on a normal install.
- packaging: icon.png is now core/firmware/leaf/scripts/icon.png, a byte-identical copy of core/firmware/rocknix/scripts/logo.png (md5 1313ba7e...). pak.json names "icon.png".
