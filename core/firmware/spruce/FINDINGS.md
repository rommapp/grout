# Spruce findings

Pinned upstream: github.com/spruceUI/spruceOS v4.6.0 (dfc2148725348419b1595e518c3bfc02b445975e), which is releases/latest. The default branch is Development. Paths below are relative to that ref.

- retroarch: left out. Spruce gives each PLATFORM its own RetroArch config, /mnt/SDCARD/Saves/ra-configs/retroarch-<PLATFORM>.cfg, falling back to the PLATFORM_PARENT name. That path is set in spruce/scripts/emu/lib/ra_functions.sh prepare_ra_config, with platform_path in spruce/scripts/helperFunctions.sh. The configs are seeded from RetroArch/platform/retroarch-<PLATFORM>.cfg.bak. They moved to Saves/ra-configs in v4.4.2 (release notes). One Fact can't express a per-PLATFORM file, and Grout only sees SPRUCE_DEVICE, which is coarser than PLATFORM. prepare_ra_config also rewrites cheevos_enable and cheevos_hardcore_mode_enable on every launch from /mnt/SDCARD/Saves/spruce/spruce-config.json (menuOptions."RetroAchievements Settings".modeToggle: Disabled, Casual, Hardcore, Manual). The hardcore reader should read that file first. The overrides folder is rgui_config_directory "./.retroarch/config" with RetroArch run from /mnt/SDCARD/RetroArch, so {card}/RetroArch/.retroarch/config (same .cfg.bak files). Needs an owner decision: a hook, or a schema key for a per-device config.
- platforms.psx saves: v2 had ["PCSX-ReARMed", "PCSX-ReARMed", "DuckSwanStation Xtreme Amped", "PCSX-ReARMed-64", "SwanStation"]; v4.6.0 has ["PCSX-ReARMed-64", "PCSX-ReARMed-32", "SwanStation", "DuckSwanStation Xtreme Amped"]. ra_functions.sh ready_architecture_dependent_states bind-mounts Saves/saves/<core>-32 or -64 over Saves/saves/<core> while RetroArch runs, for CORE_LIST "PCSX-ReARMed RACE fake-08 ChimeraSNES". At rest the real saves are in the suffixed folders. The bare folder only holds pre-split legacy files and is hidden during play, so it was dropped. Row order cannot choose the suffix, so saves.extra_folders_hook spruce_arch_saves puts <core>-<arch> first: 32 when Grout runs as 32-bit ARM (launch.sh runs grout32 exactly on the 32-bit platforms), 64 otherwise. It maps only ROM folders whose default core is in CORE_LIST: PS to PCSX-ReARMed (Emu/PS/config.json, pcsx_rearmed is default and selected on every device) and FAKE08 to fake-08 (Emu/FAKE08/config.json, fake08 only). SFC is not mapped because its selected default is mednafen_supafaust, or snes9x2010 on the Miyoo Mini, with chimerasnes optional and absent on the Mini. The snes and sfam rows are reordered to ["Supafaust", "Snes9x 2010", "Snes9x", "ChimeraSNES-64", "ChimeraSNES-32"]. MSU1 runs snes9x only, PICO8 runs native pico8, and NGP and NGPC default to mednafen_ngp with race optional, so none of those are mapped. Both suffixed folders stay in each row.
- spruce_arch_saves residual risk: upstream picks the suffix from $RA_BIN first, with PLATFORM_ARCHITECTURE as the fallback. A system set to the non-default RetroArch build (the raBuild 32-bit option on Flip, Anbernic RG XX and darkMOSS in Emu/PS/config.json) still saves to the other suffix. The same goes for a user who picks chimerasnes or race, whose suffixed folders are not ranked first.
- platforms.sfam / snes saves: v2 had "ChimeraSNES"; v4.6.0 splits it into "ChimeraSNES-64" and "ChimeraSNES-32" for the same reason (CORE_LIST), listed after the default cores.
- platforms.pico-8 saves: v2 had ["fake-08", "fake-08-64"]; v4.6.0 has ["fake-08-32", "fake-08-64"] (CORE_LIST, core_mappings.sh fake08). This now matches v2's pico row. Native PICO-8 (Emu/PICO8, the default) runs with HOME=/mnt/SDCARD/Emu/PICO8 (spruce/scripts/emu/lib/pico8_functions.sh), so its cart data is outside the save tree. Not expressible.
- platforms.gb / gbc saves: v2 had ["Gambatte", "mGBA", "TGB Dual"]; v4.6.0 has ["Gambatte", "armGBA", "mGBA", "PokeDaisy"]. Emu/GB and Emu/GBC config.json offer gambatte, armgba, mgba and pokedaisy, and no tgbdual. Folder names come from core_mappings.sh.
- platforms.gba saves: v2 had ["gpSP", "mGBA"]; v4.6.0 has ["armGBA", "gpSP", "mGBA", "PokeDaisy"]. armgba is the default (Emu/GBA/config.json).
- platforms.arduboy / dc / arcade saves: added "Arduous" (Emu/ARDUBOY) and "Flycast 2021" and "Flycast 2024" (Emu/DC, NAOMI and ATOMISWAVE offer Flycast2021-libretro and Flycast2024-libretro; core_mappings.sh).
- platforms.saturn saves: v2 had []; v4.6.0 has ["YabaSanshiro"] (yabasanshiro_generic and yabasanshiro libretro cores, core_mappings.sh). The 32-bit default "yabadabadoo" and the standalone yabasanshiro (HOME=Emu/SATURN, yaba_functions.sh) have no proven save folder.
- platforms.jaguar / j2me roms: v2 had []; v4.6.0 ships Roms/JAGUAR and Roms/J2ME. Saves are left empty. virtualjaguar, km_vjag_xtreme_amped and freej2me_plus are not in core_mappings.sh, so their library names are unproven. bigpemu-standalone keeps saves under /mnt/SDCARD/Saves/spruce/bigpemu (bigpemu_functions.sh).
- platforms.ps2: v2 had roms ["PS2"]; v4.6.0 has no PS2 folder or emulator. Written roms [].
- platforms.odyssey: v2 mapped slug odyssey to "ODYSSEY". Upstream's ODYSSEY system is labelled "Odyssey2" with core o2em (Emu/ODYSSEY/config.json). Written as odyssey-2 = ["ODYSSEY"], and the odyssey row was dropped (same fix as Knulli and ROCKNIX).
- platforms.psp: v2's "../.config/ppsspp/PSP/SAVEDATA" is confirmed. Standalone PPSSPP (the only PSP emulator, Emu/PSP default_emulator PPSSPP-SA) runs with HOME=/mnt/SDCARD/Saves, and its memstick is Saves/.config/ppsspp/PSP (spruce/scripts/emu/lib/ppsspp_functions.sh). SAVEDATA holds per-game <GAMEID> folders, not files named after the ROM, so retroarch naming does not apply there.
- platforms.nds: "dsperate" is confirmed (Emu/NDS/dsperate-configs/*.ini saves = /mnt/SDCARD/Saves/saves/dsperate). DSperate names saves <rom stem>.sav, not .srm (dsperate_functions.sh). DSperate is the default except on the A30 (DraStic-Steward) and Pixel 2 (DraStic-trngaje). DraStic keeps saves in /mnt/SDCARD/Emu/NDS/backup, outside the save tree, swapping it with backup-32 and backup-64 by arch (drastic_functions.sh). That is not expressible. Roms/NDSI (DSi, added in v4.4.2) has no row; RomM has nintendo-dsi.
- platforms, other standalone save layouts not in rows: Flycast-standalone (Saves/saves/Flycast-standalone, shared VMU files, flycast_functions.sh); mupen64plus-standalone (HOME=Emu/N64/mupen64plus, the darkMOSS default); OpenBOR (HOME=Saves/saves/OPENBOR, per-mod files in OPENBOR/Saves); scummvm-standalone (Saves/.config/scummvm-<device>/scummvm.ini, the default on every device); advmame (Saves/saves/advmame/<PLATFORM>); GameTank standalone (Saves/gametank). Libretro cores missing from core_mappings.sh (puae, km_puae_xtreme_amped, km_mame2003_xtreme, mupen64plus_next) were not added.
- platforms, candidates not changed: ATOMISWAVE (Roms/ATOMISWAVE, RomM atomiswave) is not in the arcade row, though v2 put NAOMI there. Unmapped systems include CHAI, COCO, DOOM, EASYRPG, GAMETANK, LOOPY, MKXP-Z, QUAKE, WOLF, MEDIA, ports and A30PORTS. PyUI also accepts each system's alternativeFolderNames (for example PSX and psx for PS, Emu/PS/config.json; added in v4.1.0). Only the canonical folder is listed.
- devices / launch.sh: the launch script's PLATFORM cases (A30, Brick, SmartPro, SmartProS, BrickPro, Pixel2, Flip, MiyooMini, Anbernic*) match what helperFunctions.sh sets. Every Anbernic H700 name starts with "Anbernic". Platforms upstream now sets that launch.sh does not name all fall through to the generic 64-bit branch with no SPRUCE_DEVICE: BrickOakMOSS (the TrimUI Brick on oakMOSS), Zero28, Zero40, XU20, V90S, V20, RGB30, RGB20SX, RG353M, Miniloong, A10Mini, A10MiniV4, and the other darkMOSS cfgs (E5Plus, G350, V10, XUMiniM). Their cfgs give PLATFORM_ARCHITECTURE aarch64, so grout64 is right, and trimui and generic behave the same in Grout. The Sprig fallback targets spruceUI/sprigUI, which is archived (last release sprigUI-v1.3.1). It also forces MiyooMini on any card that has a /mnt/SDCARD/sprig folder. Spruce itself always exports PLATFORM before apps start (runtime.sh and principal.sh source helperFunctions.sh).
- version.file: {card}/spruce/spruce holds "4.6.0" (App/PyUI/py-ui-config.json cfwVersionFile). Release notes from v4.0.0 to v4.6.0 show no change to Roms, BIOS, Saves/saves or Imgs. The changes they do show are RetroArch configs moving to Saves/ra-configs (v4.4.2), Roms/NDSI added (v4.4.2) and Roms/PORTS renamed to ports (v4.4.0). None of these touch a field in the file, so nothing is ranged.
- gamelist (miyoo): App/PyUI/main-ui/menus/games/utils/miyoo_game_list.py lines 50-52 read path, image and name; lines 47-48 read the id and source attributes.
