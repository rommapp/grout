# ROCKNIX findings

Pinned upstream: github.com/ROCKNIX/distribution 20261101 (cefc14339a4ae18c02bb69888f27835e50664b60). It is releases/latest; the default branch is next. Paths below are relative to that ref unless they name another repo.

- upstream (second repo): EmulationStation is ROCKNIX/emulationstation-next at f6c542872e3850c5f432929ead219547a897cd4a (projects/ROCKNIX/packages/ui/emulationstation/package.mk PKG_VERSION). The art facts below that cite it are proven only there.
- art.video and art.manual: v2 had {rom_dir}/videos and {rom_dir}/manuals. These are proven only in emulationstation-next@f6c5428 es-app/src/scrapers/Scraper.cpp Scraper::getSaveAsPath (videos with suffix "-video", manuals with suffix "-manual"). No file in distribution names them per system. cloud_sync-rules.txt excludes /videos and /manuals, but only at the /storage/roms root. Both keys were left out of the file until the owner decides.
- art.bezel: v2 had {rom_dir}/bezels; no upstream source found. The ES scraper saves bezels to {rom_dir}/images/<stem>-bezel (Scraper.cpp). ROCKNIX's own bezel folder is the global /storage/roms/bezels (packages/rocknix/sources/scripts/bezels.sh, virtual/emulators/package.mk add_system_dir), not a per-system folder. The key was left out.
- art.cover: the in-repo src is the bundled tools gamelist (misc/modules/sources/gamelist.xml uses ./images/ beside the gamelist). The "-image" suffix rule is in emulationstation-next Scraper.cpp.
- saves: v2's beside-roms is confirmed. Every device's RetroArch template (projects/ROCKNIX/packages/emulators/libretro/retroarch/sources/*/retroarch.cfg, all 15) sets savefiles_in_content_dir = "true", sort_savefiles_enable = "false" and system_directory = "~/roms/bios". setsettings.sh never overrides the savefile keys. HOME is /storage (emustation.service).
- platforms.psp saves: standalone PPSSPP (ppsspp-sa) is the psp and pspminis default (virtual/emulators/package.mk). It is patched to put SAVEDATA directly in /storage/roms/psp/ as <GAMEID> folders (emulators/standalone/ppsspp-sa/patches/004-set-paths.patch, DIRECTORY_SAVEDATA). These are not files beside the ROM named after it, so a downloaded save is placed and named wrongly for PPSSPP.
  - The libretro core (ppsspp-lr, non-default) uses memstick/PSP/SAVEDATA (libretro/ppsspp-lr/patches/002-psp-path.patch). With saves in the content dir, that is most likely /storage/roms/psp/PSP/SAVEDATA, but this is unproven in-repo.
  - ppsspp-sa/scripts/psp_save_mover.sh still refers to an older /storage/roms/psp/PSP layout and nothing in the repo calls it.
  - beside-roms cannot express either layout. This needs an owner decision (a hook or a schema addition).
- platforms.nds, standalone saves: drastic-sa is the default on H700, RK3326, RK3399, RK3566, RK3576, RK3588, SM6115 and S922X. It links its backup folder to /storage/roms/nds (drastic-sa/scripts/start_drastic.sh), so saves sit beside the ROMs but are named <rom>.dsv, while saves.naming is retroarch (.srm). melonds-sa (default on SM4450, SM8250, SM8550, SDM845, SM8650, SM8750 and AMD64) has SaveFilePath=/storage/roms/nds (melonds-sa/config/*/melonDS.ini). That location is also beside the ROMs, with melonDS's own .sav naming.
- platforms, other standalone defaults not expressible:
  - saturn: yabasanshiro-sa is the default; its backup RAM location was not found in-repo.
  - ps2: armsx2-sa keeps memory cards in /storage/roms/ps2 (armsx2-sa config PCSX2.ini MemoryCards).
  - 3ds: azahar-sa keeps sdmc and nand under /storage/roms/3ds/azahar (azahar-sa/scripts/start_azahar.sh).
  - None of these are per-game files beside the ROM.
- platforms.odyssey: v2 mapped slug odyssey (1972 Magnavox Odyssey) to folder "odyssey". Upstream's odyssey folder is system odyssey2, "Odyssey 2" (config/emulators/odyssey2.conf). Written as row odyssey-2 = ["odyssey"], and the odyssey row was dropped (same fix as Knulli).
- platforms.pc-8000: v2 mapped pc-8000 to "pc88". Upstream pc88 is system pc-8800, "PC-8800" (config/emulators/pc-8800.conf). Written as row pc-8800-series = ["pc88"], and the pc-8000 row was dropped.
- platforms.tg16 / turbografx-cd: v2 had tg16 = ["pcengine", "tg16", "tg16cd"]. Upstream's tg16cd is "TurboGrafx-CD" (config/emulators/tg16cd.conf). Written tg16 = ["pcengine", "tg16"] and turbografx-cd = ["pcenginecd", "tg16cd"].
- platforms.amiga / amiga-cd32: v2 had amiga = ["amiga", "amigacd32"]. Upstream's amigacd32 is "Amiga CD32" (config/emulators/amigacd32.conf), and RomM has slug amiga-cd32. Written amiga = ["amiga"] plus a new row amiga-cd32 = ["amigacd32"].
- platforms.vic-20: v2 had roms [] (with a separate vic20 row pointing at "vic20"). vic-20 is RomM's canonical slug, and upstream's VIC-20 folder is vic20 (config/emulators/vic20.conf). Written vic-20 = ["vic20"]. The vic20 alias row is kept.
- platforms, candidates not changed or added:
  - sfam stays on "snes", although upstream has a dedicated "sfc" Super Famicom folder (config/emulators/sfc.conf). Compare famicom, which v2 maps to its own folder.
  - genesis stays on "megadrive", although upstream also has "genesis" and "megadrive-japan".
  - segacd stays on "segacd"; upstream also has "megacd".
  - Unmapped systems include atomiswave, naomi, n64dd, satellaview, sufami, uzebox, wasm4, macintosh (folder "mac"), psvita, xbox, scummvm (at /storage/.config/scummvm/games), doom, easyrpg, cps1, cps2, cps3 and others.
  - msx2, ndsiware and wiiware stay grouped under msx, nds and wii as in v2.
- platforms, per-device availability: a ROM folder exists only when the device build calls add_es_system for it (projects/ROCKNIX/packages/virtual/emulators/package.mk, per DEVICE case). For example, 3ds, ps3, wiiu and windows exist only on some SoCs. Rows were checked against config/emulators and the union of add_es_system calls, not per device.
- devices.rules rgds: "anbernic,rg-ds" is also a prefix of the RG DS Plus compatible string "anbernic,rg-ds-plus" (projects/ROCKNIX/devices/RK3566/linux/dts/rockchip/rk3568-anbernic-rg-ds-plus.dts), so the contains probe sends the RG DS Plus to rgds.json too. It is unchecked whether that mapping fits the Plus.
- version.file: /etc/release holds "<DEVICE>.<arch>-<DISTRO_VERSION>", for example "RK3566.aarch64-20261101" (scripts/image: TARGET_VERSION, DISTRO_VERSION=$(date +%Y%m%d) unless CUSTOM_VERSION). It is not sortable across devices; /etc/os-release OS_VERSION is the date alone but sits on a KEY= line. Nothing is ranged, so this is harmless. Release notes 20260601 to 20261101 show no change to paths, folders or the save layout.
- retroarch: config is /storage/.config/retroarch/retroarch.cfg (setsettings.sh RETROARCH_CONFIG, copied from /usr/config/retroarch/retroarch.cfg). runemu.sh starts RetroArch with --appendconfig /tmp/.retroarch.cfg, which setsettings.sh writes on each launch. cheevos_hardcore_mode_enable comes from the system.cfg key retroachievements.hardcore (/storage/.config/system/configs/system.cfg, setsettings.sh). The hardcore reader in the later plan should read system.cfg. "overrides" is RetroArch's native rgui_config_directory ~/.config/retroarch/config (retroarch.cfg template).
- paths.card: /storage is ROCKNIX's internal storage partition (HOME). /storage/roms is created by tmpfiles (rocknix-dirs.conf); games-internal and games-external also exist under /storage, and rocknix-automount decides what backs /storage/roms. Grout always sees /storage/roms.
- Added canonical `win` row (roms = windows, from config/emulators/windows.conf SYSTEM_PATH /storage/roms/windows). The `windows` alias row is kept, so RomM Windows games no longer fall back to a `win` folder.
- exit_actions: `killall emulationstation` on gamelist_changed. vita3k-sa/scripts/start_vita3k.sh line 259 uses it to reload gamelists; emustation.service line 15 and essway.service line 14 have Restart=always, so ES comes back. `systemctl restart essway` was not used because RK3588 with libmali runs weston.service as the UI (platforms/RK3588/090-ui_service line 11) and upstream never restarts essway.
