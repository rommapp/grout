# Allium findings

Pinned upstream: github.com/goweiwen/Allium v1.0.2 (316d9eb9d43737f5ee0f8e6e449d471a09260a28), which is releases/latest; the default branch is main. Paths below are relative to that ref.

- Second repository: Allium's RetroArch defaults are compiled into RetroArch from goweiwen/RetroArch-patch at adfb61a3ea2386ef7c21e9721362355f9dc7b061 (the submodule third-party/RetroArch-patch). patches/10000_allium_default_settings.patch sets SRAM to $ROOT/Saves/CurrentProfile/saves, system to $ROOT/BIOS and menu config to $ROOT/Saves/CurrentProfile/config. Its RetroArch submodule (libretro/RetroArch 69a4f0ea) has DEFAULT_SORT_SAVEFILES_ENABLE true. Allium v1.0.2 ships no retroarch.cfg, neither in the repo nor in allium-armv7-unknown-linux-gnueabihf.zip. In the file, paths.saves, paths.bios, saves.layout, saves.naming and bios.default therefore cite migrations/0001-retroarch-core-overrides/retroarch-core-overrides/REminiscence/retroarch_flashback.cfg. That is the only full RetroArch config in the pinned repo, and it has the same values (savefile_directory, system_directory, sort_savefiles_enable "true", sort_savefiles_by_content_enable "false", savefiles_in_content_dir "false").
- Save folder names: each one is a core's library_name. Where the core-override folder name (installed into Saves/CurrentProfile/config by static/.allium/migrations/0001-retroarch-core-overrides/run.sh) differs from the `.info` corename, the override folder was used: crocods, DOSBox-pure, fake-08, retro-8 (alpha), Supafaust, VecX, fuse, MAME 2003-Xtreme. The following default cores have no override folder, so their names come only from the corename in static/RetroArch/.retroarch/cores/<core>_libretro.info. That file is not proof of library_name: "PUAE 2021" (amiga), "FB Alpha 2012 CPS-1/CPS-2/CPS-3" (arcade), "Virtual Jaguar", "VICE xvic", "GW", "NeoCD", "FB Alpha 2012 Neo Geo", "QUASI88", "Neko Project II Kai", "Beetle PC-FX", "PX68k", "TIC-80".
- Non-default cores with no override folder were left out of rows: Beetle Lynx, Gearboy, VBA Next, fMSX, Snes9x 2002, FB Alpha 2012, MAME 2000, M.B.A-mini, UAE4ARM, DOSBox Pure 0.9.7, Neko Project II. mame2003, mame2003_midway and bsnes are named in consoles.toml, but no .so ships for them.
- odyssey: v2 had slug odyssey with roms ["ODYSSEY"] and saves ["Odyssey2"]. v1.0.2 calls the console "Odyssey 2" with core o2em. It is written as odyssey-2 = ["ODYSSEY"] with saves ["O2EM"], and the odyssey row is gone (same fix as Spruce, Knulli and ROCKNIX).
- wonderswan-color roms: v2 had ["WSC"]. v1.0.2 has a single "WonderSwanColor" console with patterns WS, wonderswan, wonderswancolor (static/.allium/config/consoles.toml). WSC matches no pattern, and .wsc matches no extension, so it is written as ["WS"]. wonderswan and wonderswan-color saves: v2 had "Beetle Cygne"; the folder is "Beetle WonderSwan".
- neo-geo-pocket-color roms: v2 had ["NGPC"]; written as ["NGP"]. NGPC only matches from v1.0.2 on, through the lowercase "ngpc" pattern from c359e8e9 (v1.0.2) plus case-insensitive matching from 995fd17c (v1.0.0).
- pico / pico-8: v2 had roms ["PICO8", "FAKE08"] and pico-8 saves ["FAKE-08"]. v1.0.2 matches "PICO" and "pico8" only; FAKE08 is not a pattern. Written as roms ["PICO"], saves ["fake-08", "retro-8 (alpha)"]. Native PICO-8 (Apps/pico.pak) bind-mounts Roms/PICO as its carts folder (static/Apps/pico.pak/script/launch.sh). Its HOME is Apps/pico.pak, so native cart saves are outside the save tree.
- n64, dc, psp, ps2, saturn, openbor, arduboy: v2 had folders (N64, DC, PSP, PS2, OPENBOR, ARDUBOY) and saves (Mupen64Plus-Next, Flycast, Beetle Saturn, Ardens). v1.0.2's consoles.toml has no console for any of them, so a game there cannot launch. All are written as [].
- nds saves: v2 had ["DraStic"]. NDS runs standalone DraStic (cores.toml path .allium/cores/drastic/launch.sh). The build downloads it from steward-fu/nds v1.8 (Makefile DRASTIC_URL). The release zip has .allium/cores/drastic/drastic/backup/ and system/, which puts saves and BIOS outside Saves and BIOS. That is proven only outside the pinned repo and is not expressible, so it is written as [].
- Rows v2 left empty that upstream maps: atari800 and atari8bit ["EIGHTHUNDRED"] (Atari800), dos ["DOS"] (v2 save folder "DOSBox-Pure", now "DOSBox-pure"), jaguar ["JAGUAR"], mega-duck-slash-cougar-boy ["MEGADUCK"], neogeoaes and neogeomvs ["NEOGEO"], x1 ["SHARPX1"], zx81 ["ZX81"], 3do ["PANASONIC"] (Opera), cave-story ["NXENGINE"], pc-9800-series ["PC98"], pc-fx ["PCFX"], pc-8800-series ["PC8000"] (renamed from pc-8000, see the slug fix below).
- New rows not in v2: satellaview ["SATELLAVIEW"], sufami-turbo ["SUFAMI"], videopac-g7400 ["VIDEOPAC"] (O2EM), sgb ["SGB"] (mGBA, TGB Dual), scummvm ["SCUMMVM"].
- arcade: v2 had roms ["ARCADE"] and saves ["MAME 2003-Plus", "FB Alpha 2012 CPS-1/2/3", "FB Alpha 2012 Neo Geo", "FinalBurn Neo"]. Upstream has separate CPS1, CPS2 and CPS3 consoles, each defaulting to its fbalpha2012_cps core. They are added to arcade roms because cps1-3 are retired RomM aliases of arcade. Saves are ["MAME 2003-Plus", "FinalBurn Neo", "MAME 2003-Xtreme", "FB Alpha 2012 CPS-1", "FB Alpha 2012 CPS-2", "FB Alpha 2012 CPS-3"]. Neo Geo moved to the neogeoaes and neogeomvs rows.
- Other save folder changes against v2: acpc "CPC (CrocoDS)" became "crocods"; amiga added "PUAE"; c64 "VICE x64, fast" became "VICE x64"; g-and-w "Handheld Electronic" became "GW" (info only); psx "PCSX ReARMed" became "PCSX-ReARMed"; zxs "Fuse" became "fuse"; vectrex "vecx" became "VecX" (the last two are case only, and FAT is case-insensitive). snes and sfam "Beetle Supafaust", "Snes9x" became "Supafaust", "Snes9x", "Snes9x 2010", "Snes9x 2005", "Snes9x 2005 Plus", "ChimeraSNES". gb and gbc added "TGB Dual", "mGBA", "VBA-M". gba added "VBA-M". nes and famicom added "Nestopia". genesis, gamegear, sms and segacd added "Genesis Plus GX". odyssey "Odyssey2" became "O2EM". saturn "Beetle Saturn" was dropped.
- zx81: consoles.toml names core zx81, but no zx81_libretro.so or .info ships. 81_libretro.so ships with library name "EightyOne" (override folder EightyOne), so ZX81 games likely fail to launch. Saves written as [].
- pc-8800-series (was pc-8000): the console "PC-8000" (patterns PC8000, pc88) runs quasi88, which emulates the PC-8801, so the row uses RomM's pc-8800-series.
- scummvm and cave-story saves: left []. The libretro scummvm and nxengine save locations are not proven in the pinned repo. An override folder scummvm_standalone/.scummvmrc sets savepath Saves/CurrentProfile/saves/ScummVM_Standalone, but no console uses a standalone ScummVM.
- gba gpSP naming: static/.allium/migrations/0003-gpsp-sav-to-srm (new in v1.0.2, 1ed53e07) renames .sav to .srm, but under Saves/CurrentProfile/gpSP, not Saves/CurrentProfile/saves/gpSP. The gpSP override (gpSP/gpSP.opt) still sets gpsp_save_method = "gpSP". It is unclear whether gpSP writes .srm or .sav on v1.0.2.
- Unmapped consoles (no clear RomM slug or no v2 row): Game Tank, Sega VMU, Ports Collection, SH Launcher, ChaiLove, Daphne, EasyRPG, Wolfenstein 3D, Game Music Emu, LOVE, Palm OS, TI-83, Doom, Flashback, Thomson, Quake, MicroW8, Uzebox, Rick Dangerous, Movies. "GCE Vectrex" has the pattern "VECRTEX", an upstream typo.
- Folder names: only the first pattern of each console is listed. get_console_by_dir and get_console (crates/allium-launcher/src/consoles.rs) also accept every other pattern case-insensitively (PSX, PS1, NES, SNES, NGC, PKM, DS, TGB_Dual, and the ES-DE names added in v1.0.2), plus any folder whose name contains "(PATTERN)". The first patterns are unchanged from v0.29.0 to v1.0.2 (c359e8e9 only appended), so nothing is ranged.
- version.file: the Makefile package-build writes the git tag ("v1.0.2") or nightly-<hash> to .allium/version.txt. constants.rs ALLIUM_VERSION reads it. The release notes and commits from v0.29.0 to v1.0.2 show no change to Roms, BIOS, Saves/CurrentProfile/saves or Imgs. The changes that do show are the RetroArch 1.22.2 and core updates (v1.0.0), case-insensitive console matching (v1.0.0), ES-DE folder names and the gpSP migration (v1.0.2). Nothing is ranged.
- gamelist: Allium parses gamelist.xml and reads miyoogamelist.xml only when no gamelist.xml exists in that folder (crates/allium-launcher/src/entry/directory.rs). A miyoogamelist.xml written by Grout is ignored in folders that have a gamelist.xml.
- art: lazy_image.rs searches for Imgs upward from the ROM's folder, so {rom_dir}/Imgs is checked first. Box art is png, jpg, jpeg or gif named after the ROM stem.
- devices: .tmp_update/updater sets MODEL to 283 (Mini), 354 (Mini Plus) or 285 (Mini Flip). Grout has the one miyoo mapping and no device rules. v2's Allium miyoo.json differs from Spruce's miyoo.json in button "9" (15 against 10). It was copied unchanged and was not checked on hardware, the Flip in particular.
- packaging: Allium's App::new (crates/allium-launcher/src/entry/app.rs) joins config.json's icon onto the .pak directory, so a relative icon is expected. The icon is now "grout.png". The old "/mnt/SDCARD/App/Grout/grout.png" was Onion's path, and Allium has no such folder. launch.sh now sets LD_LIBRARY_PATH="$(pwd)/lib" after cd-ing into the pak's grout folder. Allium runs apps from {card}/Apps (constants.rs ALLIUM_APPS_DIR) with the .pak directory as the working directory.
- Slug fix: row `pc-8000` renamed to `pc-8800-series` (consoles.toml entry "PC-8000" uses core quasi88 with patterns PC8000 and pc88; RomM aliases pc88 to pc-8800-series).
