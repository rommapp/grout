# NextUI findings

Pinned upstream: github.com/LoveRetro/NextUI v6.15.0 (39a06dea). Paths below are relative to that ref.

- platforms.pokemon-mini: v2 had roms ["Pokemon mini (PKM)"], upstream v6.15.0 has "Pokémon mini (PKM)" (skeleton/EXTRAS/Roms/Pokémon mini (PKM)). The folder has had this name since the 2023 initial commit, so no version range. A card that already has the ASCII folder still works on device (NextUI matches by tag), but Grout now downloads into the accented folder.
- platforms.doom: v2 had roms [], upstream v6.15.0 has "Doom (PRBOOM)" (skeleton/EXTRAS/Roms/Doom (PRBOOM), skeleton/EXTRAS/Emus/tg5040/PRBOOM.pak).
- platforms.pico: v2 had saves [], upstream v6.15.0 has P8 for the "Pico-8 (P8)" folder that v2's own row lists (skeleton/EXTRAS/Saves/P8). The pico-8 row already had P8.
- platforms.snes, platforms.sfam: v2 had only "Super Nintendo Entertainment System (SFC)" and SFC, upstream v6.15.0 also ships "Super Nintendo Entertainment System (SUPA)" with Saves/SUPA (skeleton/EXTRAS/Roms, skeleton/EXTRAS/Saves/SUPA, skeleton/EXTRAS/Emus/tg5040/SUPA.pak). Added as the second folder; SFC stays the download target.
- platforms.c-plus-4: v2 had no row, upstream v6.15.0 ships "Commodore Plus4 (PLUS4)" (skeleton/EXTRAS/Roms, skeleton/EXTRAS/Emus/tg5040/PLUS4.pak). Added with saves PLUS4, the tag minarch uses (workspace/all/minarch/ma_core.c); upstream ships no skeleton/EXTRAS/Saves/PLUS4 folder.
- platforms.sgb: v2 had no row, upstream v6.15.0 ships "Super Game Boy (SGB)" with Saves/SGB (skeleton/EXTRAS/Roms, skeleton/EXTRAS/Saves/SGB). Added; sgb is in the reviewed [extra] slug list.
- platforms.3ds, dc, n64, nds, ps2, psp: v2 had "Nintendo 3DS (3DS)", "Sega Dreamcast (DC)", "Nintendo 64 (N64)", "Nintendo DS (NDS)", "Sony PlayStation 2 (PS2)", "Sony PlayStation Portable (PSP)"; no upstream source found (not in skeleton/BASE or skeleton/EXTRAS, no matching .pak). These come from third-party paks. All six are written as [].
- platforms.wonderswan, wonderswan-color: v2 had roms ["WS"] and ["WSC"]; no upstream source found. The folders have no "(TAG)" suffix, unlike every upstream folder; NextUI then uses the whole folder name as the pak name (workspace/all/common/utils.c getEmuName), so they only work with third-party WS.pak and WSC.pak. Both are written as [].
- platforms (19 save-only and empty slugs from save_directories.json other than doom: cbm-ii, chailove, chip-8, karaoke, lowres, lua, media-player, naomi, onscripter, ports, quake, rpg-maker, scummvm, ti-83, uzebox, vemulator, vircon-32, wasm-4, wolfenstein-3d): v2 had them with no ROM folder and no save folder; no upstream source found. Kept as rows with roms = [] and saves = [] as the task asked; they have no effect beyond marking the slug as known.
- platform_sources: the seven base platforms (GB, GBA, GBC, FC, MD, PS, SFC) live in skeleton/BASE/Roms and skeleton/BASE/Saves, while platform_sources holds one path per key and names skeleton/EXTRAS/Roms and skeleton/EXTRAS/Saves.
- devices.rules miyooflip and devices.quirks.miyooflip: upstream v6.15.0 builds only tg5050, tg5040 and h700 (makefile PLATFORMS); my355 is commented out there. skeleton/BOOT/common/updater still maps the Miyoo Flip to PLATFORM my355, so the rule and quirk are kept from v2 for a device the pinned release does not ship.
- devices: h700 (Anbernic H700 devices, added in v6.15.0 by PR 807, skeleton/SYSTEM/h700) has no rule and resolves to generic. Repo pak.json platforms lists tg5040, tg5050 and h700, which matches what v6.15.0 ships; its omission of my355 agrees with upstream.
- devices (source of NEXTUI_DEVICE): upstream exports PLATFORM (skeleton/SYSTEM/tg5040/paks/MinUI.pak/launch.sh); NEXTUI_DEVICE is Grout's launch.sh copy of it, not an upstream variable.
- saves.naming_hook nextui_save_format: values 0 to 3 match upstream (workspace/all/common/config.h enum, workspace/all/minarch/ma_saves.c SRAM_getPath): 0 keeps the ROM extension and adds .sav, 1 and 3 give .srm, 2 gives .sav. v2 used the first saveFormat= line; upstream CFG_init (workspace/all/common/config.c) reads every line so the last one wins. The port follows upstream.
- saves naming, formats 1 to 3: upstream strips the ROM extension only when it is 2 to 4 characters long (workspace/all/minarch/ma_saves.c formatSavePath); Grout's SaveName strips any extension. They differ only for ROM extensions of 5 or more characters.
- saves naming, archives: when useExtractedFileName=1 in minuisettings.txt, minarch names the save after the file inside a .zip instead of the .zip itself, for cores that do not load zips (workspace/all/minarch/ma_game.c Game_open, workspace/all/common/config.c). Neither v2 nor this hook reads that setting.
- bios.default: v2 wrote a BIOS file into every save-tag folder of the slug (for gba, Bios/GBA and Bios/MGBA). Upstream gives each emulator its own Bios/<TAG> (workspace/all/minarch/ma_core.c), so writing to every tag folder matches upstream. No change.
