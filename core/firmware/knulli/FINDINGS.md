# Knulli findings

Pinned upstream: github.com/knulli-cfw/knulli-linux 20260511 (c1c7de479e56691c6665723046d9f25500e5ee74), Knulli "Scarab". Paths below are relative to that ref unless they name another repo.

- upstream (repo): github.com/knulli-cfw/distribution is marked "OLD KNULLI Repository: use knulli-linux instead" and ends at 20250813 (Gladiator II). knulli-linux has a single release, 20260511, which is also releases/latest.
- upstream (second repos): knulli-linux builds packages from two git submodules pinned by the ref. The first is batocera.linux at 487014d91147610ebdd62f870009d4563ac61763 (path batocera/, used through external.mk). The second is knulli-cfw/buildroot at c2d7985b. EmulationStation is knulli-cfw/batocera-emulationstation at 4041b56a714265de81de8165b34fbd10f313a891 (package/emulationstation/knulli-emulationstation/*.mk). The facts below that cite those repos are proven only there.
- platforms.arcade: v2 had roms ["arcade", "mame", "fbneo", "neogeo"]. Upstream 20260511 has no "arcade" system (package/emulationstation/knulli-es-system/es_systems.yml), so the download target pointed at a folder Knulli never creates. Written ["mame", "fbneo", "neogeo"] with the same saves. neogeo stays third even though RomM aliases neogeo to neogeoaes (muOS removed it from arcade).
- platforms.j2me: v2 had roms [] and saves []. Upstream 20260511 has a j2me system with a libretro emulator (es_systems.yml j2me). Written ["j2me"] for roms and saves.
- platforms.msx: v2 had "msx2plus". Upstream 20260511 names the folder "msx2+" (es_systems.yml msx2+). Fixed in roms and saves. RomM has separate slugs msx2, msx2plus and msx-turbo; v2 folds all four folders into msx, and that grouping is kept.
- platforms.odyssey: v2 mapped slug odyssey (Magnavox Odyssey, 1972) to folder "odyssey2". Upstream 20260511 has no odyssey2 folder; its Odyssey 2 system is "o2em" with path o2em (es_systems.yml). RomM aliases odyssey2 to odyssey-2 (backend/utils/platform_aliases.py at 8a1e628). Written as row odyssey-2 = ["o2em"], and the odyssey row was dropped. Knulli has no system for the 1972 Odyssey. muOS may have the same slug mismatch.
- platforms.pc-8000: v2 mapped slug pc-8000 to folder "pc88". Knulli's pc88 is the PC-8800 (es_systems.yml, quasi88 core), and RomM aliases pc88 to pc-8800-series. Written as row pc-8800-series = ["pc88"], and the pc-8000 row was dropped.
- platforms.psx: v2 had roms and saves ["psx", "ps1"]. Upstream 20260511 has no ps1 system. Written ["psx"].
- platforms.psp saves: v2 had "psp/PSP/SAVEDATA". Both standalone PPSSPP (the default emulator, package/system/knulli-configgen/configs/configgen-defaults.yml psp) and the libretro core are patched to save to /userdata/saves/psp/SAVEDATA. Proof: batocera@487014d package/batocera/emulators/ppsspp/001-batocera-path.patch and package/batocera/emulators/retroarch/libretro/libretro-ppsspp/001-batocera-path.patch. Gladiator II (distribution 20250813) carries the same patches. Written ["psp/SAVEDATA"]. a133 and a527 also ship a prebuilt ppsspp_libretro.so under board/allwinner/*/fsoverlay whose save path could not be checked.
- platforms.nds saves: v2 had ["nds"]. advanced_drastic is the default on h700, a133, a527 and rk3568 (configs/configgen-defaults-*.yml), and it bind-mounts its saves to /userdata/saves/nds/advanced_drastic/saves (generators/advanced_drastic/advanced_drasticGenerator.py). "nds/advanced_drastic/saves" was added second, and nds (libretro and melonDS) stays first. Two open issues for the owner:
  - The DraStic files are <rom>.dsv while saves.naming is retroarch (.srm).
  - Plain drastic, the default on rk3326, r16, rk3128 and atm7039, keeps saves under /userdata/system/configs/drastic (generators/drastic/drasticGenerator.py copies /usr/share/drastic there). Its backup subfolder is not proven in the repo, so that folder was not added.
- platforms.nds and platforms.saturn, save order (owner decision): the order in the row cannot put advanced_drastic or yabasanshiro-sa first. With plain ROM folders the save locator always moves the save folder named after the ROM folder (nds, saturn) to the front (core/firmware/locate.go SaveLocations), and the standalone folders end in saves and yabasanshiro-sa, which never match. So a downloaded save lands in nds/ or saturn/, where advanced_drastic (the nds default on h700, a133, a527 and rk3568) and standalone yabasanshiro do not read, and it is named .srm where DraStic expects .dsv. Serving those boards needs a per-board or per-emulator rule (a hook or a schema addition), which this file cannot express today.
- platforms.saturn saves: v2 had ["saturn"]. Standalone yabasanshiro is the base default (configgen-defaults.yml saturn) and saves to /userdata/saves/saturn/yabasanshiro-sa (generators/yabasanshiro/yabasanshiroGenerator.py). It is new in Scarab. "saturn/yabasanshiro-sa" was added second. It has the same naming caveat as DraStic.
- platforms, standalone saves not added:
  - ps2: aethersx2 keeps whole memory cards in saves/ps2/pcsx2 (generators/aethersx2/aethersx2Generator.py).
  - 3ds: citra and azahar keep save data under saves/3ds/<emu> with XDG_DATA_HOME (generators/citra, generators/azahar).
  - Neither emulator stores per-game save files.
- platforms, per-board availability: knulli-es-system.py creates a ROM folder only when at least one of the system's emulator packages is enabled for the board (needFolder). Rows were checked against es_systems.yml, not against each board's package selection. ps2, 3ds and saturn, for example, exist only on some boards.
- platforms, candidates not added: 84 Knulli systems map to a known RomM slug (directly or through RomM's platform_aliases.py) and have no row. Examples: c-plus-4 (cplus4), ngc (gamecube), wii, naomi, atomiswave, amiga-cd32 (amigacd32), commodore-cdtv (amigacdtv), 64dd (n64dd), scummvm, doom (prboom), videopac-g7400 (videopacplus), atari-xegs (xegs), amstrad-gx4000 (gx4000), handheld-electronic-lcd (lcdgames), satellaview, sufami-turbo (sufami), uzebox, wasm-4 (wasm4), appleii (apple2), mac (macintosh), plus 64 more (several are x86-only systems that no Knulli board builds). Knulli's "pico" folder is Sega Pico (RomM sega-pico), not PICO-8, so the pico row correctly targets pico8.
- art.bezel: v2 had {rom_dir}/bezels; no upstream source found in knulli-linux. Knulli's EmulationStation scraper saves bezels to {rom_dir}/images/<stem>-bezel (batocera-emulationstation@4041b56 es-app/src/scrapers/Scraper.cpp Scraper::getSaveAsPath), and there is no bezels folder. The key was left out of the file.
- art.manual: the src is the ScummVM gamelist hook, which names /userdata/roms/scummvm/manuals. The general rule ({rom_dir}/manuals with suffix "-manual") is in batocera-emulationstation@4041b56 Scraper.cpp. The cover ("images", "-image") and video ("videos", "-video") rules are proven in-repo by the bundled roms/gba/gamelist.xml.
- retroarch: config is /userdata/system/configs/retroarch/retroarchcustom.cfg. configgen rewrites it on every launch (libretroRetroarchCustom.py, libretroConfig.py), and config_save_on_exit is "false". cheevos_hardcore_mode_enable is set on each launch from the knulli.conf key retroachievements.hardcore (libretroConfig.py; knulli.conf is at /userdata/system/knulli.conf per batoceraPaths.py). The hardcore reader in the later plan should read knulli.conf, not the cfg. "overrides" is Knulli's own append directory: <system>.cfg per system and <system>/<rom file>.cfg per game, keyed by the ES system name (libretroGenerator.py configToAppend). These are not RetroArch's native core-name overrides.
- version.file: /usr/share/knulli/knulli.version holds "<codename> <build date time>", for example "scarab 2026/05/11 22:15" (package/system/knulli-system/knulli-system.mk). It is not a sortable version. Gladiator II wrote /usr/share/batocera/batocera.version instead (distribution 20250813 package/batocera/core/batocera-system/batocera-system.mk), so Grout reads an empty version there. That causes no harm, because nothing in the file is ranged. Gladiator II has the same values for card, roms, bios, saves, the RetroArch paths and every row folder, so no since/until is needed.
- saves.layout per-emulator: saves are per ES system (savefile_directory = SAVES / system.name, sort_savefiles_enable false, libretroConfig.py), not per core.
- exit_actions: `knulli-es-swissknife --restart` on gamelist_changed. knulli-scripts/scripts/knulli-es-swissknife lines 87-93 stop and start S31emulationstation; knulli-scripts.mk line 64 installs it to /usr/bin; board/fsoverlay/usr/bin/knulli-install-pico8 line 101 restarts ES the same way, detached. v2 used batocera-es-swissknife, which this ref does not install, so builds that ship only that name fail the action (reported, Grout keeps working).
